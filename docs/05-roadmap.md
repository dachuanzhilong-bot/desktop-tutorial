# 05. ロードマップと受け入れ基準

| Phase | 内容 | 受け入れ基準（動くものを見せる） | 状態 |
|-------|------|----------------------------------|------|
| 1 | 設計書 | `docs/` 一式（本書） | ✅ |
| 2 | **MVP**: プリフロップ(6-max 100bb)のStudy+Practice+成績、ローカル保存、PWA | 機内モードで練習でき、記録が残り、成績画面に反映される。ソルバーの既知均衡テストが通る | ✅ |
| 3 | ポストフロップ解（代表フロップ）、ハンドを通したPractice、集計レポート | フロップ→ターン→リバーをたどって見られる。計算済みフロップの集計（テクスチャ別）が表とグラフで見られる | ✅（代表16フロップ×2シナリオ。1,755種は未） |
| 4 | Solve（WASM）、ノードロック、Range Builder | ブラウザ内でボード・レンジ・スタック・ベットサイズを指定して計算でき、進捗とExploitabilityが出る。結果をStudyで開ける | ✅（リバー/ターンは実用精度、フロップは概算。[09](09-solve-and-builder.md)） |
| 5 | Analyze（ハンド履歴）、ログイン、クラウド同期 | PokerStars/GGPokerの履歴を取り込み、EV損失順に一覧、苦手スポットから練習セットを作れる。2端末で記録が同期される | ✅（PokerStarsのみ・プリフロップを採点。同期は偽サーバーで検証、実Supabaseは未検証。[10](10-analyze-and-sync.md)） |
| 6 | MTT/ICM、仕上げ | ICM考慮のプッシュ/フォールド、アニメーション・アクセシビリティ・性能の監査(Lighthouse/axe) | ✅（プッシュ/フォールドのみ。Lighthouse・応答時間・axeを計測。[11](11-icm.md)） |

## Phase 6 で「やったこと / やっていないこと」

やった:
- **ICM プッシュ/フォールド**（2〜9人、アンティ、任意の賞金構造）: エンジンにICM用の終端を追加、WebAssemblyで計算、`/icm` 画面（ICM期待値とチップ比、ポジション別のジャム/コール範囲、ハンド別の期待値、**計算した卓からの出題と採点**）
- 検証: ICMの列挙一致、勝者総取り=従来のチップEVソルバーと同じ答え、ICMでコール範囲が狭まる、9人で解ける、実.wasmとブラウザで確認
- 仕上げの計測: Lighthouse（モバイル設定、a11y 100）、操作の応答時間（EV切替を152→32msに）、axe（新画面すべて）、静的サーバーのgzip

やっていない:
- 深いスタックのMTT、将来のブラインド/ペイジャンプの先読み、PKO、ICM練習の記録の保存・同期、実機の100ms計測、VoiceOver/TalkBackでの手動確認、未使用JSの削減（`LazyMotion`化）

## Phase 5 で「やったこと / やっていないこと」

やった:
- **Analyze**: PokerStars履歴のパーサー、席・bb正規化、プリフロップ判断のEV損失採点（練習と同じ5段階）、概要・弱点（ポジション×局面）・EV損失順の一覧と絞り込み、**ミスしたハンドで練習セット**、ヘッズアップのフロップは**レンジを復元してSolveで開く**
- **ログインと同期**: メールのワンタイムコード、`supabase/schema.sql`、記録/間隔反復/レンジ/設定の同期（ローカルファースト、オフライン可、指数バックオフ）。偽のSupabaseサーバーでの統合テスト
- 練習: 固定の問題リスト（`#set=`）

やっていない:
- GGPoker等の履歴形式、トーナメント、ポストフロップの採点（Solveで個別に調べる）、複数サイズのレイズのきめ細かい対応づけ
- 実際のSupabaseプロジェクトでの検証、削除の同期、Solve結果・ハンド履歴の同期

## Phase 4 で「やったこと / やっていないこと」

やった:
- ポストフロップ・ソルバーにノードロックを追加し、C ABI（`ffi.rs`）経由で **WebAssembly**（約130KB）にして Web Worker で実行
- **Solve**画面: ボード選択(3〜5枚)、レンジ（GTOプリセット/保存レンジ/テキスト、13×13プレビュー）、ポット・スタック、街ごとのベットサイズ、精度プリセット、進捗・残り時間・Exploitability、停止、結果をその場で閲覧（Studyと同じビュー）、保存と「Studyで開く」
- **ノードロック**: 任意のノードで戦略を固定（レンジ全体/絞り込み/選択ハンド）→再計算→解除。ロック一覧
- **Range Builder**: 13×13のドラッグ塗り、頻度ブラシ、ペア/スーテッド等の一括入力、PIO風テキストの読み書き、GTOレンジとの比較スコアと差分表示、保存・読み込み、Solveへ送る
- 保存した結果・レンジのIndexedDB(v2)、下書き保存、オフラインでもSolveが動く（Service Workerがwasm/workerをキャッシュ）

やっていない:
- ブラウザ内でのフロップ高精度計算（出荷データ並み）、マルチスレッド、サーバー実行
- 3人以上のポストフロップ、ベットサイズの自由入力
- 保存済み結果からのノードロック（再計算が必要）

## Phase 3 で「やったこと / やっていないこと」

やった:
- ポストフロップ・ソルバー（フロップ→ターン→リバー、1,326コンボ、サンプル抽象化）と検証テスト
- シナリオ2種（BTN open/BB call、BTN open/BB 3-bet/BTN call）× 代表16フロップ（計7.2MB）。レンジはプリフロップ解から切り出し
- Study(ポストフロップ): シナリオ/フロップ選択、アクションとカードをたどる、13×13（コンボ平均）＋スート別の内訳、ハンド種類(セット/トップペア/ドロー…)・ブロッカーのフィルター、戦略/EV/エクイティ/レンジ表示、エクイティ分布
- 集計レポート: ボードテクスチャ別（ハイカード・スート・つながり・ペア）のCベット頻度などと、フロップ一覧
- Practice: ポストフロップ**スポット**（ストリート指定）と**通しプレイ**（フロップ〜リバー）。プリフロップの通しプレイからヘッズアップのフロップに到達すると、そのまま続けられる。RNG・時間制限・間隔反復・採点は共通

やっていない:
- 1,755フロップの全計算、ターン/リバーの全カード、他のポジション組（CO vs BB のデータ。ソルバーは対応済み）
- ポストフロップのヒント付きの詳細解説（ボードテクスチャ別の説明文）

## Phase 2 で「やったこと / やっていないこと」

やった:
- 自作ソルバー（CFR+、3人ポット対応）、6-max 100bbのプリフロップ解（オープン・フラット・3ベット・4ベット・5ベットジャム・スクイーズ・SBリンプ）
- Study: アクションラインのたどり、13×13表(戦略/EV/エクイティ/レンジ)、ハンド詳細、ハンド種別・ブロッカーのフィルター、レンジ比較、エクイティ分布
- Practice: スポット/通しプレイ、5段階判定+スコア、解説、間隔反復、RNGモード、時間制限、ストリーク、卓のアニメーション、スワイプ/長押し/触覚/キーボード
- 成績: 正解率・平均EV損失・推移・ヒートマップ・苦手スポット→練習、日次目標、連続学習日数、書き出し/読み込み
- 日英切替、用語集(ツールチップ)、オンボーディング、ダーク/ライト、色覚配慮+模様、4色デッキ、文字サイズ、PWA(オフライン)

やっていない（次フェーズ以降）:
- 他のスタック深度(20/40/200bb)、HU・9-max、MTT/ICM
- ポストフロップ全般、Solve、Range Builder、Analyze、ログイン・同期
- プリフロップの**完全な**多人数ポット（4人以上）。`07-preflop-model.md` の近似を参照

## リスクと対策

| リスク | 対策 |
|--------|------|
| プリフロップ解がモデル依存（EQR）で、市販ソルバーと細部が異なる | 画面と文書で「近似」を明示。Phase 3 でフロップ解から実測EQRを求めて置き換える |
| WASMの速度（スレッド不可の環境） | ツリーを小さくし、単スレッドでも数十秒で収束する範囲に制限。サーバー実行はオプション |
| 解データが大きくなる（ポストフロップ） | フロップ単位のファイル分割、頻度u8/EV i16の量子化、オンデマンド取得とService Workerキャッシュ |
| ハンド履歴フォーマットの多様性 | パーサーを段階的に（PokerStars→GGPoker→他）。テストはユーザー自身の匿名化サンプルで |
| 商標 | 名称は仮。公開前に調査 |
