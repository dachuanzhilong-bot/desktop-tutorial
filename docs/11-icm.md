# 11. MTT / ICM プッシュフォールド（と仕上げの計測）

## ICM とは
トーナメントでは、チップの価値は一定ではない（チップが増えても賞金は比例して増えない）。**ICM**（Malmuth–Harville）は、残りのチップから各プレイヤーの賞金の期待値を決めるモデル。1位になる確率を `自分のチップ / 全チップ` とし、1位が決まったら残りで2位を同様に決める…を賞金の順位まで繰り返す。

`solver/src/icm.rs` の `icm_equity` が実装。チップ0（バスト）のプレイヤーは、まだチップを持つ人の後ろの最下位（複数なら等分）。

## ゲーム（`icm.rs`）
2〜9人。行動順に、スタック・SB(0.5)・BB(1)・アンティを置く。

1. 誰もジャムしていなければ、順番に **フォールド / ジャム**。全員フォールドなら BB がデッドマネーを取る。
2. 誰かがジャムしたら、後ろのプレイヤーが順に **フォールド / コール**。**最初のコールで勝負が決まる**（後ろの人はオーバーコールできない。無料のプッシュ/フォールド計算機と同じ簡略化）。全員フォールドならジャマーがデッドマネーを取る。
3. 勝負はヘッズアップのオールイン（有効スタックは小さい方、差額は返却）。勝者がポットを取る。

**ペイオフはチップではなく、結果のスタックに対する ICM の賞金期待値**。フォールドも「価値ゼロ」ではない（バストした人の分だけ他の人の期待値が増える）ので、`engine.rs` に2種類の終端を足した:

- `Kind::Const { vals }`: 全員フォールドの結果（全員の値が固定）
- `Kind::Icm { x, y, vx, vy }`: ヘッズアップのオールイン。x が勝つ場合の全員の値 `vx` と y が勝つ場合の値 `vy`。手札のエクイティ `s` に対して `vy + s·(vx−vy)`。**すでにフォールドした人も**勝者によって期待値が変わるので、その分も計算する

勝者総取り（賞金が `[1]`）だと ICM はチップに比例するので、このゲームは従来の**チップEVのプッシュ/フォールド**になる（テストで確認）。

近似: カードの重なり（ブロッカー）は相手1人ぶんだけ。3人以上がオールインになる場面（オーバーコール）は扱わない。ハンドごとのエクイティは、プリフロップのオールインのエクイティ表（169×169、各60,000サンプルのモンテカルロ）。

## 検証（`cargo test`・Vitest）
| テスト | 内容 |
|--------|------|
| ICM の数値 | 全順位の列挙（総当たり）と一致（3人・5人）、教科書の例（5000/3000/2000, 50/30/20 → 先頭 38.39）、賞金総額の保存、バスト時の扱い、勝者総取りはチップ比例 |
| ヘッズアップ・勝者総取り | **従来のプッシュ/フォールドソルバー**と同じレンジ（10bbで SB ≈58%、BB ≈37%）。新しい終端が旧い終端と同じ答えを返す |
| 3人（12/6/12bb, 50/30/20） | すべてのコールのレンジが、チップEVより 3 ポイント以上狭い。BB が最も狭い。AA は常にコール。Exploitability は賞金の0.5%未満 |
| 9人 + アンティ + 6位まで賞金 | 解け、すべての頻度が [0,1]、ノード数が 8 + 36、短いスタックほど広くジャム |
| WASM | 実際の `.wasm` を Worker 経由で動かして同じ性質を確認（`icm.wasm.test.ts`）、Playwrightでブラウザ上でも確認 |

**実際の ICMizer 等の出力との突き合わせはしていない**（公開された数表を持っていないため）。上の理論的な性質・既存ソルバーとの一致で検証している。

## 画面（`/icm`）
人数(2〜9)・各ポジションのスタック(bb)・アンティ・賞金構造（プリセット／自由入力）を指定して計算。結果: **ICM期待値とチップ比**の表、ポジション別の**ジャム範囲**と「◯◯のジャムへのコール範囲」の13×13、ハンドをタップするとジャム/コールとフォールドの期待値（賞金総額に対する％）。計算時間の目安: 3人 ≈0.5ms/反復、9人 ≈6ms/反復（標準=1,200反復）。

## ICMの練習
結果の下の「この卓で練習」: 計算した解から、**場面（そのポジションのノードを到達確率で）→ ハンド（重み×コンボ数で）**をランダムに出題。ジャム/コールかフォールドを選ぶと、通常の練習と同じ5段階（最善/正解/不正確/ミス/大ミス）で採点する。損失は賞金総額に対する％で表示し、境界は 0.005 / 0.05 / 0.2 / 0.6 %（混合頻度10%以上は「正解」）。ポジションの選択（またはランダム）、キーボード（F=フォールド、J/C/R=ジャム・コール、Enter=次へ）、触覚フィードバック対応。

## 限界
- プッシュ/フォールドのみ（スタックが十数bb以下の場面）。深いスタックのMTTツリーは解かない。
- ICMは「この1ハンドの後の賞金」を見る。将来のブラインド上昇・ペイジャンプの先読み・PKO（バウンティ）は含まない。
- 練習は計算した卓の中だけ。回答（ポジション・スタック・ハンド・選択・評価・EV損失）は端末の IndexedDB（`meta` ストアの `icm.log`、新しい2,000件）に保存し、ドリルの「これまで」と成績画面の「ICM 練習」にまとめて表示する。チップEVの練習とは単位（賞金総額の％ / bb）が違うので混ぜずに集計。バックアップのファイルには含まれ、取り込み時は端末の記録と統合する。クラウド同期の対象外（Supabase に ICM 用のテーブルが無いため）。
