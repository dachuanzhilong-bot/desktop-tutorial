# 07. プリフロップ解の近似モデルと、既知の限界

> **この解は「商用ソルバーの出力」ではありません。** 自作ソルバーが、下の近似モデルの上で求めた**そのモデルでの均衡**です。
> 学習用の目安として十分な形（オープン幅・3ベット・スクイーズなど）になるよう検証していますが、細部の頻度は商用ツールと一致しません。画面にも「近似モデル」と表示しています。

## 1. ゲーム

| 項目 | 設定 |
|------|------|
| 形式 | 6-max キャッシュ、全員100bb、SB 0.5 / BB 1、**アンティ・レーキなし** |
| 席順 | UTG, HJ, CO, BTN, SB, BB（ポストフロップはSB→BB→UTG→…→BTNの順で動く） |
| ハンド | 169クラス（スート同型）。コンボ数 6/4/12 で重み付け。**カードの重なり(ブロッカー)は2人の間で厳密に**（169×169の重なり数行列） |
| ツリー | 決定ノード6,309 / 全ノード11,520 / 終端クラス22種（`solver/src/preflop.rs`） |

### アクションとサイズ（固定）
| ライン | サイズ |
|--------|--------|
| オープン | UTG/HJ/CO/BTN 2.5bb、SB 3bb、BBのアイソ(SBリンプ後) 4bb。SBのみリンプ可（BBはチェック/レイズ） |
| 3ベット | IP: オープン×3、OOP: オープン×3+3.5。コーラーがいる(スクイーズ)場合は「コーラー1人につきオープン額を加算」。0.5bb単位に丸め |
| 4ベット | 直前のベット×2.3（0.5bb丸め）。スタックの40%以上ならジャム |
| 5ベット | オールイン |

### 多人数ポットの扱い（近似）
- 単独レイズポット（オープンに対する対応）では **最大3人** がフロップを見られる（フラット+オーバーコール）。
- 3ベット以降は **ヘッズアップのみ**（3ベットへのコールは1人まで）。4人以上のポットは存在しない。
- 3人ポットの取り分は各ペアのヘッズアップ取り分の平均 `S_i = (s_ij + s_ik)/3`（ゼロサムを保つ。実際の3人エクイティではない）。

## 2. 終端の価値（エクイティ実現モデル, EQR）
- **オールイン**: 169×169の生エクイティ表（モンテカルロ、1ペアあたり60,000サンプル、5枚ボード、カード除去対応）をそのまま使用。AA–KK=81.9%、AKs–22=50.2%、AKo–QQ=43% などの既知値と一致することをテスト。
- **フロップに進む場合**: ポストフロップは解かず、ハンドのエクイティ `e` に **実現率 R** を掛けて取り分を決める。

```
share_IP = e·R_IP / ( e·R_IP + (1−e)·R_OOP )          （ゼロサム）
payoff   = pot · share − 自分の投入額
R_role(hand) = 1 + k(SPR) · ( mean_role + slope_role · (play(hand) − 0.5) )
k(SPR)   = 1 − exp(−SPR / 3.5)          （SPRが小さいほど実現率は1に近づく）
play(hand) = ペア/スーテッド/連続度/ハイカードから作る 0〜1 の遊びやすさ指標
IP : mean=+0.10, slope=0.25      OOP: mean=−0.22, slope=0.32
```
- パラメータは「各席のオープン幅・BBのディフェンス幅が公開されている一般的な水準(UTG≈16%, CO≈27%, BTN≈45%前後)に入る」ことを基準に手で調整。**フロップ解を持たないための代用**であり、Phase 3 でフロップの実解から求めた値に置き換える。
- 画面の「EQR」欄は、このモデルが仮定した R の値（実測ではない）。

## 3. 解法
- ベクトル形式 CFR+（線形平均）、1反復≈0.12秒。**学習2,000反復 + 仕上げ4,000反復**（書き出す平均戦略は仕上げ分のみ）。
- 6人ゼロサムではないため **ナッシュ保証はない**。収束の指標は「各プレイヤーが他全員の平均戦略に対して単独で戦略を変えたときの最大の得」(best-response gain) で、最終値は **最大 0.0002bb / 平均 0.0001bb**（`manifest.json` の `info.brGainMax`）。
- **ロジットのトレンブル**: 到達確率ゼロの枝は学習されず「全員スクイーズ」のような退化した応答になり、その応答に対してフラットのEVが−16bbと評価されて、誰もフラットしなくなった（実際に発生）。学習中だけ全アクションに EV に比例した微小な確率(総計20%, λ=3)を割り当て、最後にトレンブルを切って4,000反復で平均を取り直した。結果、BTNのUTGオープンへのフラットが約9%出る。

## 5. 検証（自動テスト）
- `cargo test --release`: 7枚評価、既知エクイティ、**Kuhnポーカー(値−1/18と戦略)**、**クレアボヤント半ストリート(ブラフ頻度 b/(1+b)、MDF)**、サイズ表。`gen_pushfold`: HU プッシュ/フォールド 10bb で SB 58.3% / BB 37.4%、exploitability≈0。
- `web/src/lib/__tests__/solution.test.ts`（出力データに対して）:
  - 頻度の総和=1、フォールドEV=−投入額（UTG 0 / SB −0.5 / BB −1）
  - オープン幅が UTG<HJ<CO<BTN の順で、各レンジ幅が妥当な範囲
  - AA/KKは常にレイズ・72oは常にフォールド、BBのディフェンスは対BTN > 対UTG
  - **均衡性**: 到達確率2%以上のノードで「頻度30%以上のアクションはEV最適から0.05bb以内」、0.1%以上で0.15bb以内（実測: 最大0.031bb / 0.137bb）
  - 全ライン種別（RFI/リンプ/オープン対応/スクイーズ/3ベット/…）が存在する

## 6. 既知の限界（正直な一覧）
1. **商用ソルバーと一致しない**。特に SB はリンプ58%・レイズ10%とリンプ寄り（BBがポジションを持つため、このモデルではレイズが不利）。BBのディフェンスは広め（対BTN 67.6%）。
2. ポストフロップ未解決。EQRはモデル値。ボードやラインに応じたリアライゼーションの差は出ない。
3. 4人以上のポット、コールドコールの3ベット/4ベット、複数サイズ（ミニレイズ・複数の3ベット額）は未対応。
4. 3人ポットの取り分は近似（上記）。
5. 到達確率が低いライン（<1%）は収束が粗い（無差別になるべき頻度のEV差が最大0.14bb）。採点は「頻度10%以上のアクションは最低でも"正解"」とすることで影響を和らげている。
6. 非コンテスト側のカード除去（ヘッズアップ決着時の他の席のブロッカー）は無視。
7. 20/40/200bb、HU、9-max は未生成（ツリー生成関数はスタック・サイズをパラメータに取るので、設定を変えて再計算できる構造）。

## 7. 再生成の手順
```bash
cd solver
RUSTFLAGS="-C target-cpu=native" cargo run --release --bin gen_preflop -- --out out/cash6max-100bb   # 約15分(1スレッド)
cd ../web && npm run solutions:pack                                                                   # public/solutions/ へ gzip
```
乱数シードは固定(`--seed`)なので、同じバイナリ・同じ引数なら同じデータになる。
EQRパラメータは `--ip-mean --ip-slope --oop-mean --oop-slope --spr-scale`、トレンブルは `--explore --lambda`、仕上げは `--polish` で変更できる。
