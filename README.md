# Tessera — ポーカーGTO学習アプリ

テキサスホールデムのGTO（均衡戦略）を **調べる(Study) → 練習する(Practice) → 成績で振り返る(Stats)** ためのPWA。
スマホ片手で使えて、オフラインでも練習できる。名前・ロゴ・UI・解データはすべてオリジナル（他社の資産は一切使っていません）。

> **現在: Phase 6 完了（全フェーズの初版が揃いました）。** プリフロップ（6-max 100bb）＋ポストフロップ（代表フロップ）の Study / Practice / 集計レポート / 成績 / PWA、
> **Solve**（ブラウザ内で計算、ノードロック）、**Range Builder**、**Analyze**（PokerStarsのハンド履歴をEV損失で採点）、**ログインとクラウド同期**（Supabase）。
> **MTT/ICM プッシュフォールド**（2〜9人・賞金構造指定）と、性能・アクセシビリティの計測（[docs/11](docs/11-icm.md)）まで入っています。今後は、残っている課題の解消が中心です（下の一覧）。

## 起動方法

```bash
# Webアプリ（Node 22+）
cd web
npm ci
npm run dev            # http://localhost:3000   （開発。Service Workerは本番ビルドでのみ有効）

npm run build          # 静的書き出し → web/out/（どの静的ホスティングにも置ける）
node scripts/serve-static.mjs 3100   # out/ を http://localhost:3100 で配信（PWA/オフラインの確認用）
# 公開の手順は docs/13-hosting.md（サブパスでも動く: NEXT_PUBLIC_BASE_PATH=/<repo> npm run build）

# テスト・チェック（まとめて: npm run verify）
npm run typecheck && npm run lint    # 型チェック、ESLint（警告0が条件）
npm test                             # Vitest（ロジック・解データの検証・ファズ・表記ルール）
npm run validate:data                # 同梱の解データを全部検証（全5深度・全63フロップ・エクイティ表）
npm run e2e                          # ビルド(偽のSupabaseを設定) → Playwright（モバイル/デスクトップ、axe・タップ領域・コンソールエラー0）
npm run e2e:subpath                  # サブパス（/desktop-tutorial/）でビルド・配信して、データ・Worker・オフラインを確認（GitHub Pages 用）

# ソルバー（Rust 1.7x+, 依存crateなし）
cd solver
cargo test --release                 # 既知の均衡テスト（Kuhn / クレアボヤント / HUプッシュフォールド / エクイティ表）
cargo run --release --bin gen_pushfold                                   # HUプッシュ/フォールド表
RUSTFLAGS="-C target-cpu=native" cargo run --release --bin gen_preflop -- --out out/cash6max-100bb   # プリフロップ解の再生成(約15分)
RUSTFLAGS="-C target-cpu=native" cargo run --release --bin gen_postflop -- --out out/postflop \
    --scenario srp-btn-bb,3bp-btn-bb,srp-co-bb --flops 21 --iters 1400 --avg-from 0.5                         # ポストフロップ解(約1.5時間, 4スレッド。`--from-flop` と `scripts/merge-postflop.mjs` で追加分だけ計算して結合もできる)
cd ../web && npm run solutions:pack  # public/solutions と public/postflop にgzipで梱包

# クラウド同期（任意）: Supabaseのプロジェクトを作り、supabase/schema.sql をSQLエディタで実行、Email認証を有効にして
cp web/.env.example web/.env.local   # URLと anon キーを書き、再ビルド。詳細は docs/10

# ブラウザ内Solve用のWebAssembly（rustup target add wasm32-unknown-unknown が必要。ビルド済みの .wasm もリポジトリに入っています）
cd web && npm run wasm               # solver/ → web/public/wasm/tessera_solver.wasm
```
解データ（プリフロップ約0.17MB、ポストフロップ約14MB）はリポジトリに含まれているので、ソルバーを動かさなくてもアプリは動きます。

完成度の監査結果（作業前→作業後）は [docs/AUDIT.md](docs/AUDIT.md)、見た目の数値と画面の約束ごとは [docs/12](docs/12-design-tokens.md) にあります。

## 機能

|------|-----------|
| **Study** | **スタック深度（20/40/60/100/200bb）の切替**／アクションラインをたどって局面を移動（URLの `#n=` で共有）／13×13レンジ表を **戦略・EV・エクイティ・レンジの濃さ** で切替／タップでハンド詳細（頻度・EV・エクイティ・EQR・スート別）、長押しで頻度ポップアップ／ハンド種別（ペア・スーテッドA・スーテッドコネクター等）とブロッカーのフィルター／レンジ幅とアクション内訳／エクイティ分布グラフ／相手(レイザー)とのレンジ比較 |
| **Study (ポストフロップ)** | 3シナリオ（BTN open/BB call、BTN open/BB 3-bet/BTN call、CO open/BB call）× 代表21フロップ。**フロップ→ターン→リバー**をアクション/カードでたどる／13×13（コンボ平均）とタップで**スート別の内訳**（各コンボの頻度・EV・エクイティ）／ハンド種類（セット以上・ツーペア・トップペア・フラッシュドロー・ストレートドロー・コンボドロー・ノーペア…）とブロッカーのフィルター／戦略・EV・エクイティ・レンジ表示／エクイティ分布 |
| **集計レポート** | 計算済みフロップを**ボードテクスチャ別**（ハイカード・スート・つながり・ペア）に集計。OOPのチェック頻度、IPのCベット頻度（大小）、レンジ・エクイティを棒グラフと一覧表で。行から該当フロップのStudyを開ける |
| **Solve** | 52枚のチャートで**ボード（フロップ/ターン/リバー）**を選び、**レンジ**（GTOプリセット・保存したレンジ・テキスト）、ポット/スタック、街ごとの**ベットサイズ**、精度（ドラフト/標準/高精度）を指定→ブラウザ内（WebAssembly + Web Worker）で計算。進捗・残り時間・**Exploitability**を表示、停止も可。結果はStudyと同じビュー（ライン移動・13×13・フィルター）で見られ、**保存**して「Studyで開く」／設定を読み込み直せる。**ノードロック**: 任意のノードで戦略（レンジ全体/絞り込み/選択ハンド）を固定して相手の最適対応を再計算、解除も可。オフラインでも動く。リバー・ターン開始は実用精度、フロップは概算（[09](docs/09-solve-and-builder.md)） |
| **Range Builder** | **取り消し・やり直し**（ボタン、Ctrl/⌘+Z・Shift+Z。1回のドラッグ＝1手）／13×13を**ドラッグで塗る**（頻度ブラシ 100/75/50/25%・消しゴム、ペア/スーテッド/ブロードウェイ等の一括入力）／コンボ数・％／**PIO風テキスト**の読み込み・書き出し（`AA,KK:0.5,A5s-A2s,JTs+`）／GTOレンジ（BTN open、BB call 等）との**一致度スコア**と不足・余分の色表示／名前を付けて保存／Solveのレンジとして送る |
| **Analyze** | 数千ハンドでも画面が固まらない取り込み（進捗・中止・壊れたハンドは理由つきで除外）／**PokerStars**（と、同じ書式の **GGPoker**＝試験的）のハンド履歴（テキスト、複数ハンド）を取り込み、プリフロップの各判断を解に照らして**EV損失・5段階**で採点／概要（EV損失/100ハンド・実際の収支）／**弱点（ポジション×局面）**／EV損失順の一覧と絞り込み／各判断のアクション別頻度とEV／**「ミスしたハンドで練習セットを作る」**→そのまま練習／ヘッズアップでフロップに進んだハンドは**レンジを復元して Solve で開く**。各ハンドは**有効スタックに最も近い深度の解**で採点（15〜250bb）。端末内で処理（外には送りません） |
| **MTT / ICM** | 残り人数(2〜9)・各ポジションのスタック(bb)・アンティ・賞金構造（勝者総取り/50-30-20/9人FT/自由入力）を指定して**ICM（賞金の期待値）で**プッシュ/フォールドを計算（ブラウザ内）。ICM期待値とチップ比の表／ポジション別の**ジャム範囲**と「◯◯のジャムへのコール範囲」の13×13／ハンドの期待値（賞金総額に対する％）。**「この卓で練習」**で、計算した解から出題してEV損失（賞金総額の％）で5段階採点。回答は端末に保存され、成績画面に「ICM 練習」としてまとめて表示。バックアップにも含まれ、ログイン済みで同期が設定された場合は他の練習記録と同じアカウントへ同期される。勝者総取りは従来のチップEVソルバーと同じ答え |
| **勝率計算（Equity）** | 最大4人。各人は**特定のハンド**か**レンジ**（プリセット・保存したレンジ・テキスト）で、ボードは0・3・4・5枚。全員が1ハンドなら**全展開を数え上げた厳密な値**（2人のプリフロップで1,712,304通り）、レンジがあれば**ランダム配牌の推定値と標準誤差**を表示。勝ち・引き分けの内訳つき、52枚の表から選ぶと空いている所に入る。役判定は5枚の全2,598,960通りが教科書値と一致することをテスト（`lib/poker/eval7.ts`、`lib/poker/equity.ts`） |
| **ポーカー計算機（Odds）** | ポットとベットから、**ベットの大きさ・コールに必要なエクイティ・ポットオッズ・MDF・ブラフの割合・ブラフが損益ゼロになるフォールド率**、自分のエクイティを入れると**コールの期待値と、コールを得にするのに後で稼ぎたい額（インプライドオッズ）**。ドローのプリセットまたはアウツ数から、次の1枚・リバーまでの確率（厳密値と「2と4のルール」の目安）。**SPR**とその読み方（`lib/poker/math.ts`） |
| **ミスノート** | 成績画面に、最近の**大きなミス**（ミス・大ミス。同じ局面は新しいものだけ）を一覧。タップするとスタディの該当局面（深度・ノード・ハンド、ポストフロップはシナリオ・フロップ・ノード）が開く |
| **保存した局面** | スタディ（プリフロップ・ポストフロップ）の「この局面を保存」で星を付け、**メモ**つきで残す（スタディの「保存」タブ）。選んだハンドも含めて開き直せる。端末とバックアップに保存し、ログイン済みで同期が設定された場合は複数端末で変更・削除を同期 |
| **ログイン・同期** | メールの確認コードでログイン（Supabase）。練習の記録・間隔反復・保存レンジ・ICM練習・保存局面（メモと削除を含む）・設定を複数端末で同期（ローカルファースト、オフラインでも記録、復帰後に自動送信）。保存したSolve・取り込んだ履歴・保存レンジの削除は同期しない。未設定のビルドでは従来どおり端末内のみ |

## 品質の裏付け

- **ポストフロップ解**: 1,400反復（途中で平均を取り直し）で exploitability **ポットの0.14〜0.94%**（フロップごとに記録）。到達確率5%以上のラインでは、プレイされるアクションの最善とのEV差は最大0.55bb。実カードのリバー・クレアボヤントゲームのブラフ頻度/コール頻度が理論値と一致、O(n)ショーダウンが総当たりと一致。
- **ICM**: ICMの数値を全順位の総当たりと照合、勝者総取りのヘッズアップが従来のプッシュ/フォールドソルバーと同じレンジ、3人で全コール範囲がチップEVより狭い、9人+アンティが解ける。実 `.wasm` とブラウザでも確認。
- **性能（Lighthouse 12 モバイル設定・初回訪問・3回の中央値、gzip配信）**: Performance は**13画面すべて 91〜97**（前回より約4割遅い機械での計測。ポストフロップのスタディ 69 → 91、成績 85 → 95、ホームの初回 LCP 2.9 → 2.3秒）。Accessibility 96〜100、Best practices 96〜100（96は13×13セルの小さい文字）。表は [AUDIT §4](docs/AUDIT.md)。操作の応答は通常 ≤32ms、CPU4倍遅い想定で最大 約100〜136ms（[docs/11](docs/11-icm.md)）。
- **Analyze / 同期**: 合成のPokerStars履歴（全ポジション・オールイン・名前の特殊文字・CRLF）のパーサーと採点、2端末が収束する同期エンジン、GoTrue/PostgRESTを模した偽サーバー（1,203行のページング・`on_conflict`・`Prefer`・トークン更新）に対する統合テスト、ブラウザでのログイン→アップロード→設定同期のE2E。
- **WASM**: 実際の `.wasm` を Worker 経由で動かす統合テスト（リバーで収束→TSP1書き出し→デコード、ノードロックで固定した戦略が保たれ解除で適応が戻る）。ブラウザ（Chromium）でもフロップ/リバーを実計算してE2Eで確認。
- **ソルバー**: 既知の均衡と照合（[04](docs/04-solver-selection.md)）— Kuhn（値 −1/18・混合頻度）、クレアボヤント半ストリート（ブラフ頻度 b/(1+b)、MDF）、HUプッシュ/フォールド（10bbで SB58%/BB37%）、役の出現率、AA–KK=81.9% など。
- **プリフロップ解**（20/40/60/100/200bb）: 各プレイヤーの best-response gain（最大）は 100bb で 0.0002bb、他の深度は 0.001〜0.0015bb（20/40/60/200bbは6,000反復+仕上げ4,000反復）。出力データに対する自動テストで、オープン幅の単調性・AA/72oの扱い・フォールドEVの会計・「プレイされる頻度30%以上のアクションはEV最適」（100bbの主要ラインで最大0.031bb）を確認。各深度で、AAは常にレイズ・72oは常にフォールド・UTG<BTNを自動テスト。
- **アクセシビリティ**: axe-core（WCAG 2.1 A/AA）をE2Eで全ページ×ダーク/ライト×色覚配慮パレットに実行して違反ゼロ。配色のコントラストは4.5:1以上を計算で検証。全画面で操作要素が44px以上であることをE2Eで確認。
- **データ**: `npm run validate:data` が全5深度のプリフロップ解（木の整合・ベット額の合法性・チップの会計・**正規化前の生の頻度が100%**・値の範囲・前の行動から導かれるレンジ）と全63フロップ（生の頻度・ボードと重なるコンボが無いこと）とエクイティ表を検証。1バイト壊すと「node 0 A9s: frequencies add up to 123.5%」のように検出。
- **ロジック**: エクイティ表（AA vs KK 82% ほか）、ブラインド・オープン・3ベット・リンプ・オールイン（20/40/100bb）の会計、**間隔反復でミスしたハンドが4倍以上出る**ことを実データで測定、ショーダウンの境界ケース（ボードが役・キッカー・スチールホイール等）。
- **Analyze の頑丈さ**: 実ファイルの書式を真似た合成セッション（チャット・入退席・切断・デッドブラインド・サイドポット、GGPoker の書式差）と、それを1,500通りに壊したファズで例外ゼロ。3,000ハンドの取り込み中も画面が固まらないことをE2Eで確認。
- **コード**: ESLint（Next・TypeScript・React Hooks・jsx-a11y）と clippy（`-D warnings`）が警告0でCI必須、`any` ゼロ、ブラウザのコンソールエラーは全画面で0（E2E）。
- **オフライン**: E2Eで「初回訪問→機内モード→練習を開始し回答まで」を確認。

## ソルバーの選定（要約。詳細は [docs/04](docs/04-solver-selection.md)）

`b-inary/postflop-solver`（Cargo.tomlで **AGPL-3.0-or-later** を確認、2023年10月に開発停止）と `TexasSolver`（**AGPL-3.0**）は、ブラウザに配信するアプリに組み込むとアプリ全体のソース公開義務（AGPL §13）が及ぶため採用しない。
加えて、この開発環境では crate のダウンロード(`static.crates.io`)と GitHub の clone が遮断されていて、依存ごとビルドできない。
→ **依存なし(std のみ)の自作 CFR+ ソルバー**（`solver/`）を採用。同じコードをそのまま WebAssembly にしてブラウザで動かしている（Phase 4）。

## 残っている課題（正直なリスト）

1. **プリフロップ解は近似モデル**（[07](docs/07-preflop-model.md)）。ポストフロップを解かずEQR(エクイティ実現率)モデルで代用しているため、細部は商用ソルバーと一致しない（例: SBがリンプ寄り、BBのディフェンスが広め）。ポストフロップ解の統計からEQRを校正し直す作業は未着手。
2. **ポストフロップ解も近似**（[08](docs/08-postflop-model.md)）。ターン6枚・リバー2枚の**サンプルしたカード**で解いており、ベットサイズも少数（フロップ33%/75%、ターン66%、リバー50%/100%）。計算済みは**3シナリオ×21フロップ**のみ（1,755種のうち代表）で、集計レポートはその範囲。
3. 対応範囲: 6-max のみ。プリフロップは 20/40/60/100/200bb（**100bb以外はEQRモデルを調整しておらず、粗い近似**。[07](docs/07-preflop-model.md)）。HU・9-max は未生成。ポストフロップは100bbのみ。プリフロップは4人以上のポット・複数サイズ未対応。ポストフロップはBTN vs BB（シングルレイズ・3ベットポット）とCO vs BB（シングルレイズ）のみ。
4. 低頻度のライン（到達確率 <1%）は収束が粗い。
5. 振動(Haptics)は Vibration API のため iOS Safari では動かない。
6. 名称 "Tessera" は仮で、公開前に商標・ドメインの調査が必要（上の「ライセンスと名称」）。
7. **ブラウザ内のフロップ計算は概算**（既定設定で250反復≈ポットの3%、約22秒）。リバー・ターンは実用精度。高精度のフロップは `gen_postflop` をデスクトップで回す。WASMは単スレッド。ノードロックは計算中のソルバーにだけ有効（保存結果からはできない）。Solveは常にヘッズアップ、ベットサイズは街ごと最大3つ+オールイン。
8. **Analyze は PokerStars と GGPoker（試験的: 公開されている書式から作った合成データでのみ確認）、プリフロップのみ採点**。解は6-maxの単一レイズサイズのモデルなので、実際のサイズが違うレイズ（例: 100bbジャム）は近似で採点され、画面に注記される。ポストフロップは採点せず、Solveで個別に調べる。他のサイトは未対応。
9. **クラウド同期は実際のSupabaseプロジェクトでは未検証**（偽サーバーでのみ検証、[10](docs/10-analyze-and-sync.md)）。Solveの結果・ハンド履歴は同期しない。保存レンジの削除も同期しない。保存局面の削除は墓標を同期する。
10. **ICMはプッシュ/フォールドのみ**（浅いスタック向け）。オーバーコールなし、将来のブラインド/ペイジャンプの先読みなし、PKOなし。練習は計算した卓の中だけ。練習の記録は保存局面とともにクラウド同期に対応（実Supabaseは未確認）。**既知のICMツールの出力との突き合わせはしていない**（理論的な性質と既存ソルバーとの一致で検証）。
11. 実機での100ms反応計測とスクリーンリーダー(VoiceOver/TalkBack)の手動確認は未実施（手順は [AUDIT §7](docs/AUDIT.md)）。Lighthouse は13画面すべて90以上だが、遅い機械では1回ごとに±5点ほど動く（[AUDIT §4](docs/AUDIT.md)）。
12. 記録・保存したSolve/レンジ/ハンド履歴は、ログインしなければ端末内(IndexedDB)のみ。書き出し/読み込みでバックアップ可能（Solveの結果は大きいのでレンジとハンド履歴まで）。
13. 開発用ツールに `npm audit` の警告（vitest 3 の依存など）。配信物には含まれない。vitest の大きな版上げで解消予定。
