# Tessera — ポーカーGTO学習アプリ

テキサスホールデムのGTO（均衡戦略）を **調べる(Study) → 練習する(Practice) → 成績で振り返る(Stats)** ためのPWA。
スマホ片手で使えて、オフラインでも練習できる。名前・ロゴ・UI・解データはすべてオリジナル（他社の資産は一切使っていません）。

> **現在: Phase 3 完了。** プリフロップ（6-max 100bb）＋ポストフロップ（代表フロップ）の Study / Practice / 集計レポート / 成績 / PWA。
> Solve・Range Builder・Analyze・ログイン/同期・MTT は次のフェーズ（[ロードマップ](docs/05-roadmap.md)）。

## 起動方法

```bash
# Webアプリ（Node 22+）
cd web
npm ci
npm run dev            # http://localhost:3000   （開発。Service Workerは本番ビルドでのみ有効）

npm run build          # 静的書き出し → web/out/（どの静的ホスティングにも置ける）
node scripts/serve-static.mjs 3100   # out/ を http://localhost:3100 で配信（PWA/オフラインの確認用）

# テスト
npm run typecheck && npm test        # Vitest（ロジック・解データの検証）
npm run e2e                          # ビルド → Playwright（モバイル/デスクトップ、axeアクセシビリティ監査込み）

# ソルバー（Rust 1.7x+, 依存crateなし）
cd solver
cargo test --release                 # 既知の均衡テスト（Kuhn / クレアボヤント / HUプッシュフォールド / エクイティ表）
cargo run --release --bin gen_pushfold                                   # HUプッシュ/フォールド表
RUSTFLAGS="-C target-cpu=native" cargo run --release --bin gen_preflop -- --out out/cash6max-100bb   # プリフロップ解の再生成(約15分)
RUSTFLAGS="-C target-cpu=native" cargo run --release --bin gen_postflop -- --out out/postflop \
    --scenario srp-btn-bb,3bp-btn-bb --flops 16 --iters 1400 --avg-from 0.5                         # ポストフロップ解(約40分, 4スレッド)
cd ../web && npm run solutions:pack  # public/solutions と public/postflop にgzipで梱包
```
解データ（プリフロップ約0.17MB、ポストフロップ約7.2MB）はリポジトリに含まれているので、ソルバーを動かさなくてもアプリは動きます。

## 品質の裏付け

- **ポストフロップ解**: 1,400反復（途中で平均を取り直し）で exploitability **ポットの0.16〜0.83%**（フロップごとに記録）。到達確率5%以上のラインでは、プレイされるアクションの最善とのEV差は最大0.55bb。実カードのリバー・クレアボヤントゲームのブラフ頻度/コール頻度が理論値と一致、O(n)ショーダウンが総当たりと一致。
- **ソルバー**: 既知の均衡と照合（[04](docs/04-solver-selection.md)）— Kuhn（値 −1/18・混合頻度）、クレアボヤント半ストリート（ブラフ頻度 b/(1+b)、MDF）、HUプッシュ/フォールド（10bbで SB58%/BB37%）、役の出現率、AA–KK=81.9% など。
- **プリフロップ解**: 6,000反復、各プレイヤーの best-response gain は最大 **0.0002bb**。出力データに対する自動テストで、オープン幅の単調性・AA/72oの扱い・フォールドEVの会計・「プレイされる頻度30%以上のアクションはEV最適」（主要ラインで最大0.031bb）を確認。
- **アクセシビリティ**: axe-core（WCAG 2.1 A/AA）をE2Eで全ページ×ダーク/ライト×色覚配慮パレットに実行して違反ゼロ。配色のコントラストは4.5:1以上を計算で検証。
- **オフライン**: E2Eで「初回訪問→機内モード→練習を開始し回答まで」を確認。

## ソルバーの選定（要約。詳細は [docs/04](docs/04-solver-selection.md)）

`b-inary/postflop-solver`（Cargo.tomlで **AGPL-3.0-or-later** を確認、2023年10月に開発停止）と `TexasSolver`（**AGPL-3.0**）は、ブラウザに配信するアプリに組み込むとアプリ全体のソース公開義務（AGPL §13）が及ぶため採用しない。
加えて、この開発環境では crate のダウンロード(`static.crates.io`)と GitHub の clone が遮断されていて、依存ごとビルドできない。
→ **依存なし(std のみ)の自作 CFR+ ソルバー**（`solver/`）を採用。Phase 4 でそのまま WebAssembly にする。

## 残っている課題（正直なリスト）

1. **プリフロップ解は近似モデル**（[07](docs/07-preflop-model.md)）。ポストフロップを解かずEQR(エクイティ実現率)モデルで代用しているため、細部は商用ソルバーと一致しない（例: SBがリンプ寄り、BBのディフェンスが広め）。ポストフロップ解の統計からEQRを校正し直す作業は未着手。
2. **ポストフロップ解も近似**（[08](docs/08-postflop-model.md)）。ターン6枚・リバー2枚の**サンプルしたカード**で解いており、ベットサイズも少数（フロップ33%/75%、ターン66%、リバー50%/100%）。計算済みは**2シナリオ×16フロップ**のみ（1,755種のうち代表）で、集計レポートはその範囲。
3. 対応範囲: 6-max 100bb のみ。20/40/200bb・HU・9-max・MTT/ICM は未生成。プリフロップは4人以上のポット・複数サイズ未対応。ポストフロップにCO vs BB等のデータは未書き出し（ソルバーは対応済み）。
4. 低頻度のライン（到達確率 <1%）は収束が粗い。
5. 計測していない項目: 100ms以内の操作反応の実機計測、スクリーンリーダー(VoiceOver/TalkBack)での手動確認（Phase 6）。
6. 振動(Haptics)は Vibration API のため iOS Safari では動かない。
7. ライセンスファイル未作成（下の質問を参照）。名称 "Tessera" は仮で、商標調査が必要。
8. Solve・Range Builder・Analyze・ログイン/クラウド同期・MTT/ICM は未実装（設計は [02](docs/02-data-model.md)・[05](docs/05-roadmap.md)）。記録は端末内(IndexedDB)のみ。書き出し/読み込みでバックアップ可能。
